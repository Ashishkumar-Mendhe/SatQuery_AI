## 10D owner-scoped context and follow-ups

The protected conversation API persists a bounded validated AOI, selected source IDs and UTC dates, prior dated optical candidate scenes within that AOI, recent tool/job/result references, and the latest **committed** analysis reference under `(owner_id, access_scope, conversation_id)`. It stores no raw user text, result prose, credentials or expiring URLs. An optimistic version check prevents stale writes. Explicit AOI/scene replacement invalidates dependent context; a delayed execution returns `stale` without its result body. A queued job remains a queued reference; subsequent turns recheck the latest job via existing owner-authorized service status and committed artifact/result access before promotion. `GET` and `DELETE` use the same owner/scope filter; deletion removes the conversation binding, not separately owned jobs or artifacts.

“Compare it with the earlier image” resolves only one dated earlier optical candidate. “What about this area?” needs an AOI and a prior supported intent. “Show that change on the map” resolves only a committed change artifact; the actual map action remains `unavailable` until the separately authorized 10E bridge. Ambiguous references get a specific clarification. This is bounded context, not the future full session/history product or a claim of live DB/browser operation.
